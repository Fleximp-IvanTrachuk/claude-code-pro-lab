# Следующие шаги

Что уже сделано и что делать дальше, чтобы запустить проект через spec-kit.

## Уже сделано

- Установлен `uv` (через Homebrew).
- Продумана целевая архитектура: мастерская на DuckLake → витрина StarRocks → self-service BI
  (раздел «Целевая архитектура» в [speckit-prompts.md](speckit-prompts.md)).
- Подготовлены тексты для команд spec-kit и дорожная карта из 5 этапов: [speckit-prompts.md](speckit-prompts.md).
- Написаны `README.md` (на украинском) и `CLAUDE.md`.
- spec-kit **ещё не установлен** в репозиторий: команду инициализации нужно запустить вручную (шаг 2).

## Шаг 1. Закоммитить текущее состояние

Чтобы потом в `git diff` было видно, какие файлы добавил spec-kit:

```bash
git add .gitignore .claude/settings.json README.md CLAUDE.md docs/
git commit -m "Add project concept, README, CLAUDE.md and spec-kit prompts"
git push
```

`git push` нужен, чтобы README появился на GitHub и проект можно было подключить
в claude.ai для голосового изучения с телефона.

## Шаг 2. Установить spec-kit в репозиторий

В корне репозитория:

```bash
uvx --from git+https://github.com/github/spec-kit.git@v1.1.2 specify init --here --integration claude --script sh
```

Команда спросит подтверждение, потому что папка не пустая, — ответьте «да».
После этого посмотрите, что изменилось: `git status`. Появятся папка `.specify/`
(шаблоны и скрипты) и команды в `.claude/`.

## Шаг 3. Перезапустить Claude Code

Без перезапуска команды `/speckit.*` не появятся.

## Шаг 3a. Положить реальные файлы

Скопируйте файлы дистрибьюторов в `data/private/`, включая старые версии: на них
будем отрабатывать изменения структуры. Папка уже исключена из git. Перед каждым
коммитом проверяйте `git status`: реальных файлов там быть не должно.

Работать с данными через Claude Code можно только после обезличивания (фича 001).

## Шаг 4. Конституция — правила проекта

1. Прочитайте блок конституции в разделе 1 файла [speckit-prompts.md](speckit-prompts.md)
   и поправьте, если что-то не так. Каталог DuckLake на этапе 1 — файл
   `data/lake/catalog.ducklake`, на этапе 2 он переезжает в Postgres (это уже учтено).
2. Введите `/speckit.constitution` и вставьте этот блок.
3. Прочитайте получившийся `.specify/memory/constitution.md` и сверьте с исходным текстом.

## Шаг 5. Первая фича (001)

| Команда | Что вставить / сделать | Результат |
|---|---|---|
| `/speckit.specify` | блок из раздела 3 файла с промптами | ветка `001-...` и `spec.md` |
| `/speckit.clarify` | ответить на вопросы, в том числе три открытых вопроса из брифа | уточнённый `spec.md` |
| `/speckit.plan` | можно без текста: стек уже в конституции | `plan.md`, модель данных |
| `/speckit.tasks` | — | `tasks.md`, список задач |
| `/speckit.analyze` | — | проверка согласованности spec / plan / tasks |
| `/speckit.implement` | писать ключевые куски кода самому там, где Claude попросит | код и тесты |

Каждый получившийся документ стоит прочитать до перехода к следующей команде:
ошибку в спецификации исправить дешевле, чем в коде.

## Шпаргалка по терминам

- **uv** — менеджер Python-проектов: ставит нужную версию Python, создаёт окружение,
  управляет зависимостями (`uv add`), запускает код (`uv run`) и утилиты без установки (`uvx`).
  Нужен, потому что системный Python — 3.9, а проекту требуется 3.11+.
- **Мастерская и витрина** — два хранилища с разными ролями. Мастерская (DuckLake) — где
  данные очищают и маппят. Витрина (StarRocks) — куда попадает только чистое и откуда строят отчёты.
- **Слои мастерской**: `raw` (сырые файлы как есть) → `normalized` (единая схема) →
  `aggregates` (служебные агрегаты для маппинга: что не замаплено и сколько это весит).
- **DuckLake** — расширение DuckDB: каталог с метаданными и снапшотами хранится в базе,
  данные — в Parquet-файлах. Даёт транзакции и time travel (запрос к прошлой версии данных).
- **Мастер-данные** — эталонные справочники: продукты (SKU), области, клиенты.
  **Data steward** — человек, который следит за их качеством и маппит новые значения.
- **Docker / docker compose** — запуск сервисов в изолированных контейнерах; compose описывает
  несколько связанных сервисов в одном файле и поднимает их одной командой.
- **StarRocks** — аналитическая база-сервер для многих пользователей и BI; подключение по MySQL-протоколу.
- **Superset** — веб-инструмент self-service BI: датасеты, графики, дашборды без программирования.
- **Streamlit** — библиотека для веб-интерфейсов на чистом Python; здесь — UI маппинга.
- **PR (Pull Request)** — запрос на GitHub влить изменения из своей ветки в `main`.
  На странице PR видно все изменения; проверяющий оставляет комментарии, после
  одобрения ветка вливается.
- **spec-kit** — процесс «сначала спецификация, потом код»: конституция → спецификация →
  уточнения → план → задачи → реализация. Каждый шаг — markdown-документ в репозитории.
